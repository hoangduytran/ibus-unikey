# ${ts}_breakup_setup

## Objective

Break up `setup/*` (UI + settings glue) into modular components for maintenance, testability, and clarity.

## Source guidance

From planning notes (section `## ✅ Best way to modularize setup/* for UI + settings glue`):
- 3 logical submodules: UI layer, settings layer, controller/glue
- minimal entrypoint, explicit interfaces, state sync, focused UI files, unit-testable config and controller core

## Module layout

1. `setup/ui/` (or `setup/view/`)
   - GTK UI definitions: `.ui` files (main window, macro dialog, etc.)
   - `SetupView` class: create, update, read widget states, show/hide dialogs
   - UI helpers: builder load, set signal connections, style updates

2. `setup/config/` (or `setup/settings/`)
   - `SettingsStore` class: load/save options, default state, migration
   - Wrappers for each option: `setMacroEnabled`, `isMacroEnabled`, etc.
   - Integration with GSettings schema and/or `.ini` fallback

3. `setup/controller/` (or `setup/handlers/`)
   - `SetupController` class: owns references to view + settings + engine API
   - Signal callbacks: `onMacroEdit`, `onApply`, `onReset`
   - Validation and transformation between UI values and settings state

## Entry point (minimal)

- `setup/main.cpp`:
  - initialize GSettings
  - construct `SetupView`, `SettingsStore`, and `SetupController`
  - call `controller.init(); gtk_main();`;
  - cleanup on exit

## Interfaces (header contracts)

`setup/ui/SetupView.h`:
- `void showMacroDialog();`
- `void setOptionState(...);`
- `std::string getMacroText();`
- `void connectMacroEdit(std::function<void()> callback);`

`setup/config/SettingsStore.h`:
- `void loadDefaults();`
- `void applyDefaults();`
- `void setMacroEnabled(bool);`
- `bool isMacroEnabled();`

`setup/controller/SetupController.h`:
- `void onMacroEditClicked();`
- `void onApplyClicked();`
- `void onResetClicked();`

## Detailed steps

1. Create directories:
   - `setup/ui` (or `view`), `setup/config` (or `settings`), `setup/controller` (or `handlers`)
2. Move or refactor current `setup/*` into corresponding submodules
3. Make `setup/setup` existing APIs (if needed) call through to controller
4. Update `setup/CMakeLists.txt` to build each directory, include headers
5. Add tests:
   - `tests/setup/test_settings_store.cpp` (no GTK)
   - `tests/setup/test_controller_with_mock_view.cpp`
6. Keep `setup/ibus-setup-unikey` or UI bootstrap minimal

## Notes

- Keep one source of truth for defaults in `org.freedesktop.ibus.engine.unikey.gschema.xml` and `SettingsStore`.
- Keep `signal_handlers.cpp` trimmed to wiring only; move logic into `SetupController`.
