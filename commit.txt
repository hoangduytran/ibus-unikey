Reason for this change
- `ukengine/tables/usrkeymap.cpp` contains important parsing and serialization paths that were difficult to follow because the intent of each step was mostly implicit.
- The keymap data table formatting in `ukengine/tables/data.cpp` needed a readability pass so large table blocks are easier to scan and maintain without changing behavior.
- We want this pass to stay non-functional: improve maintainability and reviewer clarity while preserving existing logic and output.

What changed
- Added detailed explanatory comments in `ukengine/tables/usrkeymap.cpp` for:
  - label table purpose and count derivation
  - config-line parsing flow (`parseNameValue`)
  - key layout loading progression (`UkLoadKeyMap`, `UkLoadKeyOrderMap`)
  - map initialization and key-order map persistence (`initKeyMap`, `UkStoreKeyOrderMap`)
  - event-label lookup semantics (`getLabelIndex`)
- Added/expanded API-style function documentation blocks around major exported/helper functions in `ukengine/tables/usrkeymap.cpp`.
- Reformatted the top-level initializer structure in `ukengine/tables/data.cpp` to improve visual grouping/indentation consistency for large single-byte table entries; no data values were intentionally changed.
- Updated this `commit.txt` to serve as the PR body and accurately describe this commit.
