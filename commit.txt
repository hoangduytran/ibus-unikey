feat(setup): macro interchange handlers with library-backed codecs

## Why

ibus-unikey users need to import/export macros in formats common on other platforms
(Espanso YAML, generic JSON, Apple text-replacement plist, CSV/TSV) without maintaining
fragile hand-rolled parsers. Using well-tested libraries reduces corner-case bugs, improves
binary plist and structured YAML support, and keeps CI honest about real dependencies.

## What changed

### Interchange architecture

- **Registry:** `MacroFormatHandlerRegistry` maps `MacroInterchangeForcedFormat` and lowercase
  file suffixes to handler factories (thread-safe; factories run outside the registry lock).
- **Dispatch:** `macro_file_io.cpp` routes import/export by explicit format or AUTO from the path.
- **Shared utilities:** `macro_interchange_common.cpp` centralizes `GError` domain helpers, file
  slurping, extension sniffing, `StdVnChar` folding order, and UTF-8 encoding for export.

### Codecs (per-handler TU + static registration)

- **Text:** `macro_handler_text.cpp` still delegates to `TextMacroFormat` for native `.txt`/`.macro`.
- **JSON:** `macro_handler_json.cpp` uses **json-glib** (arrays of `{trigger, content}` or flat maps).
- **Plist:** `macro_handler_plist.cpp` uses **libplist** for XML and binary plists (`shortcut`/`phrase`,
  `replace`/`with` aliases).
- **YAML:** `macro_handler_yaml.cpp` uses **yaml-cpp** for Espanso-shaped `matches:` sequences.
- **CSV/TSV:** `macro_handler_csv.cpp` uses **libcsv** for parsing and `csv_write` for export
  (all fields quoted; valid RFC-style output).

### UI and ergonomics

- **`macro_dialog_state.cpp` / header:** Persists macro file chooser last directory via config;
  migrates invalid paths to `~/Documents`.
- **`macro_export_filename.cpp` / header:** Normalizes export basenames vs selected filter extension.
- **`macro_utils.cpp`:** Clearer naming for list-store ↔ `CMacroTable` mirroring (last-wins policy).

### Engine / docs

- **`text_macro_format.cpp`:** Comments and export/import documentation aligned with interchange
  behavior (no semantic breakage intended).

### Build & CI

- **`setup/CMakeLists.txt`:** `pkg_check_modules` / `find_*` for **json-glib**, **libplist**,
  **libcsv**, **yaml-cpp**; link `yaml-cpp::yaml-cpp` and other deps on `macro_interchange`.
- **`.travis.yml`:** Installs `libjson-glib-dev`, `libplist-dev`, `libcsv-dev`, `libyaml-cpp-dev`
  (plus existing GTK/ibus packages).

### Developer experience

- **`.clangd`:** Uses `CompilationDatabase: build` so clangd resolves GTK/plist/json-glib/yaml-cpp
  includes when `build/compile_commands.json` exists.
- **`.gitignore`:** Stop ignoring `.clangd` so the project can ship a minimal config.

### Tests

- **Existing `tests/macros/` tree** (already tracked) remains the canonical macro interchange coverage:
  `macro_file_io_test` loads fixtures by extension (`*.txt`, `*.yaml`, `*.plist`, `*.json`, `*.csv`),
  plus dialog-state and export-filename tests. No behavioral change required in those sources for
  this commit; they validate the new libraries at link/runtime.

*(A duplicate `tests/UI/macros/` layout with stale `src/setup/` paths was **not** added; use
`tests/macros/` only.)*
